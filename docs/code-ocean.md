# Running on Code Ocean

The repository doubles as a Code Ocean capsule. `environment/Dockerfile` builds
the compute environment, `code/run` is the entry point, and `code/app.py` maps
App Panel fields onto the renderer.

Capsule: [`26f5aa46-1c66-45b1-812b-a9bad1335ee9`](https://codeocean.allenneuraldynamics.org/capsule/2162568)

## Why two assets

The glass brain does not depend on which neurons are drawn, so it is rendered
once and stored as a data asset. A render run then composites onto it:

| | |
|---|---|
| Building both 10 µm views and four structure overlays | 59 min |
| Rendering 8 cells onto the cached views | 38 s |

Measured on this capsule, runs `f729af51` and `645ec55d`.

## The cache asset

`ccf_glass_render_cache_10um` — `714793b5-0772-46bb-aa13-c2e55f06a29f`, 11 files,
38 MB. Holds sagittal and iso at 10 µm plus `TH`, `MD`, `Isocortex` and `CP`
overlays for each. **Attach it with mount name `ccf_cache`.**

The app finds it by that mount name, or by any mount containing a `views/`
directory. Without it the capsule still runs, building the views in-process and
saying so in the log — slow, but never silently so.

To rebuild or extend it, run with `mode = build_cache` and no data assets
attached, then create a data asset from the run:

```json
{"name": "ccf_glass_render_cache_10um",
 "mount": "ccf_cache",
 "source": {"computation": {"id": "<computation_id>", "path": "ccf_cache"}}}
```

`source.computation.path` matters. Omit it and the asset is rooted at `/results`,
so the views mount one level too deep and the app reports no cache found.

## Setting up the App Panel

App Panel parameters cannot be created through the API — `.codeocean/app-panel.json`
is generated by the UI and is read-only. Build them in **Build Mode → Parameters**.

Set `code/run` as the File to Run, and make every parameter **Named**, not
Ordered. All of them are optional, so they can be added one at a time without
breaking existing runs.

| Name | Type | Default | Notes |
|---|---|---|---|
| `mode` | list | `render` | `render`, `build_cache` |
| `views` | list | `sagittal,iso` | `sagittal`, `iso`, `coronal`, `dorsal`, `sagittal,iso` |
| `resolution` | list | `10` | `10`, `20`. A list, not free text — anything but a multiple of 10 is rejected |
| `colors` | list | blank | `vivid`, `allen`, `okabe-ito`, `tab10`, `set1`, `dark2`, `dark`, `husl`, `viridis`, `turbo` |
| `thickness` | input | blank | Tube radius in 20 µm pixels; blank means 1.15 |
| `compartment` | list | `all` | `all`, `axon`, `dendrite`, `soma` |
| `structure` | input | blank | CCF acronyms, comma separated; needs a cached overlay |
| `sample` | input | blank | Seeded random subset |
| `cells` | input | blank | Explicit ids, comma separated |
| `seed` | input | blank | Changes the colour assignment |
| `label` | input | `cells` | Output filename prefix |
| `dpi` | input | `300` | |
| `formats` | list | `png,svg` | |

`profile`, `asset`, `subdir` and `cache` are deliberately left off the panel.
They override where data comes from, and exposing them invites a run that
silently reads the wrong thing. They remain available from the API for
debugging.

## Reconstruction inputs

Attach reconstruction assets in the panel; the app discovers them. It looks for
`ccf_space_reconstructions/swc` inside each, falling back to a recursive `.swc`
search, and treats every mount except the cache as neuron data.

For a one-off, the `asset` parameter takes an `s3://` URI instead:

```
s3://aind-open-data/exaSPIM_685221_2024-04-12_11-46-38_reconstructions_2026-08-28_23-04-54
```

## Reading run status

`end_status` alone is not enough. A failed run on this capsule reported
`end_status: succeeded` with `exit_code: 2` and `has_results: false`. Check all
three, and treat `has_results: false` as failure whatever the others say.

## Environment

The base image must come from the deployment's own registry; a Docker Hub image
is rejected at launch with `invalid base image registry`.

The renderer is installed from a pinned commit of this repository rather than
from the capsule's own files, so a released capsule names exactly the code it
ran. Bump `RENDERER_REF` in `environment/Dockerfile` to pick up new work.
